> [`jiggle/bone_chain_modifier.gd`](../jiggle/bone_chain_modifier.gd),

## 왜 사슬은 스프링으로 풀지 않는가

데모 02의 [`JiggleSpring`](../jiggle/jiggle_spring.gd)을 여러 개 이어서 머리카락을 만들면 안 된다.

- 스프링은 **힘 → 가속도 → 속도 → 위치** 순으로 계산한다.
- 사슬로 이으면 각 스프링의 강성이 서로 간섭한다.
- 뻣뻣하게 만들려고 k를 키우는 순간 발산한다. (데모 01의 발산 실험과 같은 이유)

Verlet은 반대로 간다.

- **위치를 직접 고쳐서** 제약을 만족시킨다.
- 속도는 이전 위치와의 차이로 *유추*하므로, 위치를 옮기면 속도도 자동으로 맞춰진다.
- 제약을 몇 개 걸든, 사슬이 몇 개든 발산하지 않는다.

이게 천·머리카락·밧줄이 전부 Verlet(또는 그 후손인 PBD/XPBD)로 구현되는 이유다.

## Verlet 적분

```gdscript
var velocity := (positions[i] - previous[i]) * (1.0 - drag)
previous[i] = positions[i]
positions[i] += velocity + accel * delta * delta
```

속도 변수가 없다. `previous`가 곧 속도 정보다. 그래서 다음 두 가지가 공짜로 따라온다.

| 하고 싶은 일 | 스프링이라면 | Verlet이라면 |
| --- | --- | --- |
| 길이 고정 | 강한 스프링 → 발산 위험 | 위치를 목표 거리로 옮기면 끝 |
| 벽 뚫지 않기 | 반발력 계산 + 계수 튜닝 | 표면 위로 옮기면 끝 |

**대신 고정 timestep이 필수다.** `dt`가 프레임마다 흔들리면 `(p - p_prev)`가 속도를 잘못 표현한다.
스프링보다 훨씬 민감하다. 이 프로젝트는 모디파이어 안에서 1/120초로 쪼갠다.

## 제약 반복 횟수 = 뻣뻣함

거리 제약은 이웃한 두 입자를 목표 길이가 되도록 당기거나 민다.

```gdscript
var correction := offset * ((distance - rest_lengths[i]) / distance) * constraint_stiffness
positions[i] += correction * (weight_a / total)
positions[i + 1] -= correction * (weight_b / total)
```

문제는 **하나를 고치면 옆 구간이 다시 어긋난다**는 것이다. 그래서 여러 번 반복한다.
반복할수록 오차가 줄고, 사슬은 뻣뻣해진다.

> 데모에서 **반복 횟수**를 1로 내리고 초록 그래프(길이 오차)를 보라.
> 오차가 치솟고 머리카락이 고무줄처럼 늘어난다. 12로 올리면 즉시 원래대로 돌아온다.
> **사슬이 길수록(본 개수 ↑) 같은 반복 횟수로는 오차가 커진다** — 제약이 끝까지 전달되기 어렵기 때문.

역질량(`inverse_mass`)이 0인 입자는 어떤 제약도 못 움직인다. 루트를 이걸로 고정한다.
스켈레톤이 위치를 정하는 지점이라 시뮬레이션이 건드리면 안 되기 때문이다.

## 각도 제한 — 그리고 리그 형상이 만드는 함정

이웃한 두 구간이 꺾일 수 있는 각도를 제한한다. 없으면 머리카락이 자기 위로 접히면서
스킨드 튜브가 안팎으로 뒤집힌다.

첫 구간은 비교 대상이 없으므로 **rest 방향**을 기준으로 삼는다. 여기에 함정이 있다.

> 이 데모를 만들 때 실제로 겪은 버그:
> 머리카락 뿌리를 머리 **꼭대기**에 심고, 첫 마디가 머리 표면을 타고 옆으로 뻗게 만들었다.
> 그랬더니 첫 구간의 rest 방향이 거의 수평이 되었고, 35° 제한 때문에
> **머리카락이 영영 아래로 못 내려오고 옆으로 뻗친 채 굳었다.**
>
> 해결: 뿌리를 헤어라인 높이로 내리고 첫 마디부터 거의 아래를 보게 만들었다.
> 시뮬레이션 코드는 한 줄도 안 고쳤다. **리그 형상 하나가 결과를 통째로 결정한다.**

## 모양 유지 — 거리와 각도만으로는 무엇이든 축 늘어진다

거리 제약은 **길이**만 지키고 각도 제한은 **한계각**만 막는다.
그 사이에서 사슬이 어떤 모양이 되든 아무도 상관하지 않는다.
그래서 중력만 걸어 두면 치마든 리본이든 굵은 머리채든 **축 늘어진 밧줄**이 된다.

실제 천·리본·머리채는 두께가 있어 원래 형태를 어느 정도 유지한다.
`shape_stiffness` 가 그 성질이다. 각 마디를
**앞 마디가 실제로 돌아간 만큼 따라 돌린 자리**로 끌어당긴다.

```gdscript
# 앞 마디의 rest 방향 → 현재 방향 의 회전
var swing := Quaternion(previous_rest, previous_current)
# 그 회전을 이번 마디의 rest 방향에 먹인 자리가 "모양을 지켰다면 있었을 위치"
var target := positions[i] + (swing * rest_direction) * rest_lengths[i]
positions[i + 1] = positions[i + 1].lerp(target, _shape_per_iteration)
```

**절대 방향이 아니라 앞 마디 기준 상대 방향을 되돌리는 것이 핵심이다.**
절대 방향으로 하면 사슬이 통째로 굳어 아예 흔들리지 않는다.

`restore_stiffness` 와 헷갈리기 쉬운데 하는 일이 다르다.

| | 하는 일 |
| --- | --- |
| `restore_stiffness` | 절대 위치를 rest 로 끌어당긴다 — 사슬 전체를 제자리로 |
| `shape_stiffness` | 상대 방향을 rest 로 되돌린다 — **꺾이는 것만** 막는다 |

그래서 모양 유지는 **흔들림은 그대로 두고 처짐만** 없앤다.
데모 09 실측(정지 상태 치마 처짐): `0` → `0.1076m`, `0.40` → `0.0063m`.

> 반복 루프 안에서 걸리므로 **반복 횟수로 나눠 둔다** (`1 - pow(1-s, 1/iterations)`).
> 안 그러면 아래 충돌 마찰과 똑같이 반복 횟수를 올릴 때마다 소리 없이 뻣뻣해진다.
> 반복 횟수는 *제약을 얼마나 정확히 푸는가*여야지 *재질이 얼마나 단단한가*가 되면 안 된다.

### 그런데 되돌리는 것만으로는 스프링이 된다

여기서 **아래 충돌 절과 정확히 같은 함정**을 한 번 더 밟았다.
위 코드는 `positions` 만 옮기고 `previous` 를 안 건드린다.
Verlet은 속도를 `p - p_prev` 로 유추하므로 **그 이동이 통째로 속도가 된다.**
되돌리는 힘이 전부 운동에너지로 바뀌어 반대편으로 넘어간다 — 고무판이 된다.

착지처럼 힘이 확 들어오는 순간에 이게 가장 크게 드러난다.

```gdscript
var correction := (target - positions[i + 1]) * _shape_per_iteration
positions[i + 1] += correction
# previous 를 같이 옮긴 만큼 그 속도가 사라진다. 0이면 아예 안 생긴다.
previous[i + 1] += correction * (1.0 - shape_elasticity)
```

실측(점프 반복, 구동만으로 방향 전환 4회가 나오는 조건):

| `shape_elasticity` | 0.0 | 0.35 | 0.7 | 1.0 |
| --- | --- | --- | --- | --- |
| 방향 전환 | **4** | 8 | 12 | 12 |

**탄성 0에서는 `shape_stiffness` 를 0 → 0.7로 올려도 4로 고정된다.**
"모양은 유지하지만 튀지는 않는" 재질 — 실제 천 · 가죽 · 두꺼운 리본이 그렇다.

> Verlet에서 위치를 옮기는 코드를 새로 쓸 때는 **`previous` 를 어떻게 할지 반드시
> 같이 정해야 한다.** 안 정하면 기본값이 "에너지 주입"이다.

## 충돌 — 사고의 90%가 여기서 나온다

파고든 입자를 표면 위로 옮기면 끝… 이 아니다. **밀어낸 뒤 속도를 어떻게 할지**가 전부다.
데모의 `충돌 응답 방식` 슬라이더로 세 단계를 직접 비교할 수 있다.

### ① 위치만 밀기 — 폭주한다

```gdscript
positions[i] = target
```

Verlet은 이 이동을 **속도로 착각한다**(`v ≈ p - p_prev`). 표면에 눌린 입자는
매 스텝 밀려나며 매번 새 속도를 얻고, 그 에너지가 누적되어 무한대로 날아간다.

> 이 프로젝트에서 실제로 난 사고다. 파티클이 1e19까지 갔고,
> `Vector3.normalized()`가 float 오버플로로 **0 벡터**를 돌려주면서
> `Quaternion(from, to)` 가 "The vectors must not be zero" 에러를 쏟아냈다.

### ② 이전 위치도 같이 밀기 — 폭주는 없지만 튄다

```gdscript
previous[i] += target - positions[i]
positions[i] = target
```

속도가 정확히 보존되므로 에너지는 안 늘어난다. 하지만 **파고들던 속도가 그대로 남아**
다음 스텝에 또 파고들고 또 밀려난다. 게다가 반복마다 이 보정을 하면,
거리 제약이 도로 끌어당긴 만큼까지 `previous`에 누적되어 있지도 않은 속도가 생긴다.

### ③ 접촉 안정화 — 법선 속도를 버린다 (기본값)

밀어내기는 반복 안에서 위치만 고치고, **속도 보정은 스텝당 한 번만** 한다.

```gdscript
var tangent := velocity - normal * velocity.dot(normal)
previous[i] = positions[i] - tangent * retain     # 법선 성분을 통째로 버린다
```

- 파고들던 속도가 사라진다 → 다음 스텝에 또 파고들지 않는다 (안 튄다)
- 밀어내기가 만든 바깥쪽 속도도 같이 사라진다 → 에너지가 늘 수 없다 (안 터진다)
- 접선 성분은 밀어내기의 영향을 안 받으므로, 남는 건 **충돌 전의 진짜 접선 속도**다

마찰은 반복 안이 아니라 스텝당 한 번만 걸어야 한다. 반복 안에서 걸면
반복 횟수를 올릴 때마다 머리카락이 점점 끈끈해진다.

충돌체는 전부 **캡슐 하나로 통일**했다. 두 점이 같으면 그냥 구가 되므로 코드 경로가 하나로 줄어든다.

## 사례 연구 — "옆머리만 튄다"

데모를 돌려 보면 **옆·앞머리는 흔들릴 때마다 튀는데 뒷머리는 차분한** 현상이 있었다.
"마찰 때문에 자연스럽게 생기는 차이인가?"라는 질문에서 출발해 실제로 측정했다.

측정 지표는 끝점 위치의 **2차 차분**(가속도) 평균과, 연속한 2차 차분의 **교대성**
(매 프레임 방향이 뒤집히면 +, 유지되면 −).

| 조건 | 닿는 가닥 | 안 닿는 가닥 | 결론 |
| --- | --- | --- | --- |
| 충돌 끔 | 1.07 | 1.07 | **8가닥 완전히 동일** → 리그·스프링에는 비대칭이 없다 |
| 충돌 켬 | 3.6 ~ 5.2 | ~1.0 | 원인은 100% 충돌 |
| 반복 6 → 16 | 4.8 → 5.6 | ~1.0 | **개선 없음** |
| 마찰 0.2 → 0.6 | 4.5 | ~1.0 | **개선 없음** |
| 머리 길이 4마디 | 0.95 | 0.95 | **완전히 사라짐** |

교대성은 어느 조건에서나 **−0.2 ~ −0.3(음수)** 이었다. 즉 매 프레임 방향이 뒤집히는
수치 채터가 아니라, **진짜 접촉 동역학**이었다.

원인은 리그 형상이었다. 기본 길이 머리카락의 끝이 어깨 캡슐 **안쪽 26mm 지점**에 있었다.

- 복원력은 그 rest 위치(= 어깨 속)로 계속 당긴다
- 충돌은 계속 밀어낸다
- 자극이 올 때마다 그 가닥만 표면에 끌리며 다른 가닥과 다르게 움직인다

어깨 높이를 내려 기본 자세가 충돌체를 벗어나게 하자 **8가닥이 전부 1.07로 균일**해졌다.

### 여기서 얻을 교훈

> **rest 자세가 충돌체 안에 파묻히면, 시뮬레이션 파라미터로는 절대 못 고친다.**

파라미터 튜닝은 "얼마나 출렁일까"를 정하는 데 쓰는 것이지, 아티팩트를 덮는 데 쓰는 게 아니다.
같아야 할 부위가 서로 다르게 움직인다면 그건 튜닝 대상이 아니라 **버그**다.

실무에서 쓰는 판별법:

1. **충돌을 꺼 본다.** 차이가 사라지면 원인은 충돌, 남으면 리그·파라미터.
2. **대칭인 부위끼리 비교한다.** 좌우가 다르면 리그가 비대칭이거나 축 부호가 틀렸다.
3. **파라미터를 극단으로 밀어 본다.** 아무 반응이 없으면 그건 원인이 아니다.

그래서 이 데모는 **지금 충돌 중인 입자를 빨간 구로 표시**한다.
어느 가닥이 표면에 끌리고 있는지 눈으로 바로 확인하라고 넣은 것이다.

긴 머리 프리셋처럼 머리카락이 **실제로 어깨에 얹히는** 경우에는 접촉이 정상이다.
이때는 접촉 동역학이 남지만(1.3~1.8), 튀는 수준(5~7)과는 전혀 다르다.

## 안전장치는 선택이 아니다

시뮬레이션은 언제든 폭주할 수 있다는 전제로 짜야 한다.

```gdscript
func _enforce_safety() -> void:
	var limit := _total_rest_length * 2.0 + 1.0
	for i in range(1, positions.size()):
		var length := (positions[i] - positions[0]).length()
		if is_finite(length) and length <= limit:
			continue
		reset_to(rest_positions)   # 조용히 rest 자세로 되돌린다
		return
```

한 번 무한대가 나오면 그 프레임부터 메쉬가 통째로 사라지고 원인 추적도 어려워진다.
"터졌으면 조용히 원위치" 가 훨씬 낫다.

## 파티클 → 본 회전 (데모 02의 확장)

원리는 데모 02와 같다. 다만 **루트부터 끝까지 순서대로** 처리해야 한다.
각 본의 회전을 계산하려면 부모의 최종 자세가 먼저 정해져 있어야 하기 때문이다.

```gdscript
for i in _bones.size():
	var origin := world * rest.origin                       # 재구성된 본 원점
	var desired := (parent_basis.inverse() * (chain.positions[i + 1] - origin)).normalized()
	var swing := Quaternion(rest_direction, desired)
	skeleton.set_bone_pose_rotation(_bones[i], swing * rest_rotation)
	world = world * Transform3D(Basis(swing) * rest.basis, rest.origin)   # 다음 본의 부모
```

스켈레톤 캐시(`get_bone_global_pose`)에 의존하지 않고 **직접 누적**한다.
자기가 방금 쓴 값을 다시 읽는 구조는 미묘한 순서 버그를 만든다.

중간 본의 "끝 방향"은 축을 가정하지 않고 **자식 본이 어디 붙어 있는지**로 구한다.

```gdscript
_local_tips.append(_rests[i + 1].origin.normalized())
```

리그마다 본 축이 제각각이라, 이렇게 하면 남의 리그에 붙일 때 훨씬 덜 깨진다.

## 파티클과 본 사슬은 서로 다르다

**본은 늘어나지 않는다.** 재구성된 사슬은 항상 정확한 rest 길이를 쓴다.
반면 파티클은 제약이 덜 풀리면 늘어나 있다.

화면에서 **노랑 십자(파티클)와 흰 선(본 사슬)이 벌어진 정도**가 곧
"제약이 얼마나 덜 풀렸는가"다. 반복 횟수를 1로 내리면 눈에 띄게 벌어진다.

## 튜브 스키닝

머리카락 다발은 [`ProcSkin.add_tube`](../common/proc_skin.gd)로 만든 진짜 스킨드 메쉬다.
두 가지가 중요하다.

**1. 가중치 전이** — 구간 중앙에서 그 본 100%, 관절에서 이웃과 50:50.

```gdscript
if u < 0.5:
	return {previous_bone: 0.5 - u, current: 0.5 + u}
return {current: 1.5 - u, next_bone: u - 0.5}
```

이게 없으면 관절마다 표면이 각지게 꺾인다.

**2. 평행 이송(parallel transport)** — 링마다 프레임을 새로 만들면 튜브가 제멋대로 꼬인다.
이전 링의 기준 벡터를 새 접선에 수직으로 투영해서 이어 간다.

```gdscript
var right := reference - tangent * reference.dot(tangent)
right = right.normalized()
reference = right
```

> 데모의 **본 색 보기**를 켜면 정점 색으로 구워 둔 본 인덱스가 보인다.
> 관절에서 색이 섞이는 폭이 곧 전이 구간이다.

## 해볼 것

1. **반복 횟수 1 → 12** 를 왕복한다. 초록 그래프(길이 오차)와 머리카락의 뻣뻣함을 함께 본다.
2. **본 개수**를 12로 올린다. 끝이 어깨에 닿기 시작하면서 **빨간 구**가 뜨고,
   그 가닥만 다르게 움직인다. 위 사례 연구를 눈으로 재현하는 것이다.
3. **충돌 응답 방식**을 ① → ② → ③ 으로 바꿔 본다. ①은 폭주(안전장치가 rest로 되돌린다),
   ②는 표면에서 튐, ③은 안정.
4. **각도 제한 0** + 자극 세게 → 머리카락이 접히며 튜브가 뒤집힌다.
5. **충돌 끄기** → 머리카락이 머리와 어깨를 통과한다. 그리고 8가닥이 완전히 똑같이 움직인다.
6. **복원 진동수 0** → 한 번 흐트러진 머리가 영영 제자리로 안 돌아온다.
7. `S`로 슬로우모션 + `몸통 회전` 자극 → 파도가 뿌리에서 끝으로 전파되는 게 보인다.
   사슬 시뮬레이션의 가장 중요한 시각적 특징이다.
