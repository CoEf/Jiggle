# 10 · 실제 캐릭터에 붙이기

> 코드: [`demos/09_real_character/`](../demos/09_real_character/),
> [`tools/inspect_rig.gd`](../tools/inspect_rig.gd),
> [`tools/character_test.gd`](../tools/character_test.gd)

데모 01~08은 전부 **코드로 만든 리그**를 썼다. 본 축이 단위행렬이고, 이름도 내가 정했고,
rest 자세가 충돌체에 파묻힐 일도 없었다. **그 조건에서 잘 도는 것은 아무것도 증명하지 않는다.**

이 단계에서는 밖에서 가져온 Rigify 캐릭터(`assets/adachi_rigged4/adachi_rigged4.glb`, 본 183개)에
이 프로젝트의 모디파이어를 그대로 붙였다. 새로 짠 시뮬레이션 코드는 한 줄도 없다 — 설정만 했다.

## 붙이기 전에 리그를 먼저 찍는다

```bash
godot --headless --path <프로젝트> --script tools/inspect_rig.gd
```

**축은 절대 추측하지 않는다.** 틀려도 에러가 안 나기 때문에, 틀린 채로 몇 시간을 보낼 수 있다.
이 도구는 본 목록·rest 위치와 함께 두 가지를 통계로 뽑아 준다.

| 찍어 본 것 | 이 리그의 답 |
| --- | --- |
| 본이 뻗은 방향 | **+Y : 117개** (자식이 하나인 본 전부). 자작 리그는 단위행렬이라 +Z 였다 |
| 사슬 후보 | 머리카락 4마디 ×5 · 치마 4마디 ×12 · 리본 4마디 ×2 · 손가락·팔다리 |

여기서 얻은 결론이 곧 설정값이다.

```gdscript
modifier.tip_axis = JiggleBoneModifier3D.TipAxis.Y   # 가슴
modifier.tip_axis = Vector3.UP                        # 사슬
```

## 리그마다 달랐던 것 네 가지

| | 자작 리그 (데모 01~08) | 실제 리그 |
| --- | --- | --- |
| 본 축 | 단위행렬 (로컬 = 월드) | 로컬 **+Y** |
| 본 이름 | 내가 정함 | `breast.L` · `Hair_Fringe.001` · `Dress_S.L.001` |
| 흔들 대상 수 | 8가닥 | **37가닥** — 그룹별로 켜고 끌 수 있어야 한다 |
| 충돌체 | 코드로 위치 계산 | `BoneAttachment3D` + `JiggleCollider3D` 로 본에 붙임 |

이름은 규칙으로 찾는다. `Hair_` · `Dress_` 접두어로 시작하고 **위쪽이 끊긴 지점**
(부모가 다른 그룹이거나 부모가 갈래진 곳)을 사슬의 뿌리로 삼아 한 줄로 내려간다.
개수를 세어 두지 않고 규칙으로 찾으므로, 가닥이 늘어난 모델을 넣어도 코드를 안 고쳐도 된다.

단, 규칙으로 못 찾는 것이 하나 있었다. 이 리그는 **앞리본 왼쪽 뿌리 본 이름이 `Back`** 이다
(오른쪽은 `Front_Ribbon_Side.01.R` 로 멀쩡하다). 규칙만 보면 리본이 아니라서
**그 한 가닥이 에러도 경고도 없이 통째로 빠졌다.** 규칙을 넓히면 다른 리그에서 진짜 등뼈를
잡으므로, 규칙은 그대로 두고 예외 표(`CharacterRig.MISNAMED_BONES`)로 잡는다.
표에 적힌 이름은 눈에 보이지만 규칙 안에 숨은 예외는 안 보인다.

충돌체 반지름은 **절대값으로 박으면 안 된다.** 다른 모델에서 전부 틀린다.
이 코드는 `thigh.L`↔`thigh.R` 거리(골반 너비)를 기준자로 삼아 비율로 정한다.

비율 자체는 결국 **눈으로 맞춰야 한다.** 골반·허벅지는 처음 계산한 비율이 그대로 맞았지만,
머리는 안 맞았다 — `Head` 본 원점이 목 밑이라 구가 턱 밑에 박히고 머리통은 비어 있었다.
씬에서 맞춰 본 결과 반지름 0.60 → 1.065, 중심은 위로 2.0 · 뒤로 0.5(골반 너비 배수)였다.
중심을 반지름에 묶어 두면 안 된다는 것도 이때 나왔다. 묶어 두면 충돌체를 키울 때
구가 머리 위로 떠올라 **키울수록 안 막는다.**

> 너무 작아 서브스텝이 거의 안 돌았기 때문이다.
>
> 표의 값은 검사가 고정한 조건([`BASELINE`](../tools/character_test.gd))에서 잰 것이지
> **데모 기본값이 아니다.** 데모 기본값은 실제 캐릭터 씬에서 눈으로 맞춘 값이라
> 공기 저항이 훨씬 높고(0.5), 그 값에서는 정지 잔떨림이 37가닥 전부 0.00000 이다.

읽는 법:

- **네 그룹이 전부 0이 아니다** → 가슴·머리카락·치마·리본에 모디파이어가 실제로 붙었다.
- **모양 유지를 끄면 정지 처짐이 치마 0.0267 → 0.1039m (4배)** 로 늘어난다 → 아래 "모양 유지" 참고.
- **충돌을 끄면 파고듦이 0 → 0.0515m** 로 늘어난다 → 충돌체가 실제로 막고 있었다는 뜻이다.
  단, **모양 유지를 끄고 충돌체를 2배로 키운 상태**에서 비교해야 한다 —
  기본 크기에서는 치마가 다리에 거의 안 닿아 껐다 켜도 차이가 안 난다(아래 함정 ③).
- **축오차 0.0° vs 90.0°** → 아래 함정 ① 참고.
- **파묻힘 0.0000** → rest 자세가 충돌체 안에 들어가 있지 않다. 이 값이 0이 아니면
  파라미터로는 절대 못 고치고 충돌체를 줄여야 한다.
- **잔떨림 0.00205** → 자극이 없을 때 프레임당 이만큼 움직인다. 0이 아닌 이유는
  이 리그의 **앞머리가 머리 충돌체에 닿아 있어서**다. 공기 저항을 0.03 까지 낮춘
  검사 조건에서만 보이는 접촉 떨림이고, 데모 기본값(0.5)에서는 0.00000 이다.
- **비용 3.3ms** (사슬 37가닥 × 충돌체 4개, 반복 6~8회). 모양 유지를 끄면 2.7ms,
  충돌까지 끄면 1.2ms — **충돌 검사가 비용의 절반이다.**

## 모양 유지 — 축 늘어지는 문제

처음 붙였을 때 치마·리본·머리카락이 **전부 축 늘어졌다.** 원인은 파라미터가 아니라
**제약이 하나 없었던 것**이다.

```
거리 제약    이웃한 두 입자의 간격    → 길이만 지킨다
각도 제한    꺾일 수 있는 최대 각도   → 한계각만 막는다
   그 사이의 모양은 아무도 안 지킨다  ← 여기가 비어 있었다
```

그래서 중력만 걸면 무엇이든 **축 늘어진 밧줄**이 된다. 실제 치마·리본·굵은 머리채는
두께가 있어 원래 형태를 어느 정도 유지한다. 그 성질이 `JiggleVerletChain.shape_stiffness` 다.

각 마디를 **앞 마디가 실제로 돌아간 만큼 따라 돌린 자리**로 끌어당긴다.

```
앞 마디의 rest 방향 → 현재 방향  의 회전을 구한다
그 회전을 이번 마디의 rest 방향에 먹인다
그 방향으로 rest 길이만큼 간 자리가 "모양을 지켰다면 있었을 위치"다
```

절대 방향이 아니라 **앞 마디 기준 상대 방향**을 되돌리는 것이 핵심이다.
절대 방향으로 하면 사슬이 통째로 굳어 아예 흔들리지 않는다.

`restore_stiffness` 와는 다른 일을 한다.

| | 하는 일 |
| --- | --- |
| `restore_stiffness` | 절대 위치를 rest 로 끌어당긴다 — 사슬 전체를 제자리로 |
| `shape_stiffness` | 앞 마디 기준 상대 방향을 rest 로 되돌린다 — **꺾이는 것만** 막는다 |

측정 결과(정지 상태 처짐):

| | 모양 유지 켬 | 끔 | 비 |
| --- | --- | --- | --- |
| 머리카락 (0.20) | 0.0339 m | 0.0566 m | 1.7배 |
| 치마 (0.40) | 0.0063 m | 0.1076 m | **17배** |
| 리본 (0.20) | 0.0368 m | 0.1860 m | 5배 |

흔들림을 죽이지도 않는다 — 걷기에서 치마 끝점이 여전히 0.09m 움직인다.

**반복 횟수로 나눠 둔다.** 제약 반복 루프 안에서 같은 비율을 매번 곱하면
반복 횟수를 올릴 때마다 소리 없이 뻣뻣해진다(충돌 마찰에서 이미 당한 함정).

```gdscript
_shape_per_iteration = 1.0 - pow(1.0 - shape_stiffness, 1.0 / iterations)
```

반복 횟수는 **제약을 얼마나 정확히 푸는가**여야지 **재질이 얼마나 단단한가**가 되면 안 된다.

## "너무 고무 같다" — 어느 손잡이인가

점프 자극을 주면 흔들림이 **고무공이나 스프링처럼 통통 튀어** 보일 때가 있다.
직관적으로는 "모양 유지를 높이고 중력을 낮추면 되겠다" 싶지만 **둘 다 틀린 처방이다.**

문제는 "뻣뻣하게 하고 싶다"는 한 문장 안에 **서로 다른 세 증상**이 섞여 있다는 것이다.

| 증상 | 지표 | 손잡이 |
| --- | --- | --- |
| **착지 순간 튄다** | 착지 왕복 | **`shape_elasticity` ↓** · `restore_frequency` ↓ |
| 한 번 흔들리면 오래 출렁인다 | 잔향 왕복 · 정착 | 가슴 `damping_ratio` ↑ · 사슬 `drag` ↑ |
| 너무 많이 휜다 | 진폭 | `angle_limit` ↓ · `gravity` ↑ · `shape_stiffness` ↑ |
| 축 늘어진다 | 처짐 | `shape_stiffness` ↑ |

첫 줄이 이 절의 핵심이다. **착지처럼 힘이 확 들어오는 순간의 튐은 감쇠로도 잘 안 잡힌다** —
원인이 감쇠 부족이 아니라 제약이 **없던 에너지를 만들어 내는** 것이기 때문이다.

`tools/material_sweep.gd` 로 한 번에 하나씩만 바꿔 실측한 결과다.

```bash
godot --headless --path <프로젝트> --script tools/material_sweep.gd
```

측정 방식이 두 가지다. **각 방식으로 잴 수 없는 값은 표에 아예 안 찍는다.**

| | 방법 | 읽을 수 있는 것 |
| --- | --- | --- |
| **잔향** | 좌우로 흔들다 자극을 끊고 스스로 멈추는 과정을 본다 | 왕복 · 정착 |
| **착지** | 점프를 반복시키고 자극을 안 끊는다 | 진폭 · 왕복 |

잔향의 진폭은 "풀어준 순간 어디까지 밀려 있었나"라 파라미터가 아니라 위상이 정한다.
착지의 정착은 자극이 안 끊기니 개념 자체가 없다.
**착지의 왕복은 구동만으로 4가 나온다 — 4를 넘는 만큼이 재질의 떨림이다.**

### 착지에서 튀는 진짜 원인은 `shape_elasticity` 였다

`shape_stiffness` 는 입자를 목표 위치로 끌어당긴다. 그런데 Verlet은 속도를 저장하지 않고
`p - p_prev` 로 유추하므로, **그 이동을 통째로 속도로 착각한다.** 되돌리는 힘이 전부
운동에너지가 되어 반대편으로 넘어간다 = 스프링.

`shape_elasticity` 로 그 속도를 얼마나 남길지 정한다(0이면 `previous` 도 같이 옮겨 속도가 안 생긴다).

| `shape_elasticity` (모양 유지 0.4 고정) | 진폭m | **왕복** |
| --- | --- | --- |
| 0.00 | 0.1503 | **4** ← 구동만, 재질은 안 떤다 |
| 0.35 | 0.0981 | 8 |
| 0.70 | 0.0785 | **12** |
| 1.00 | 0.0704 | **12** ← 예전 동작 |

**그리고 탄성을 0으로 두면 모양 유지를 아무리 올려도 착지 떨림이 안 늘어난다.**

| `shape_stiffness` (탄성 0 고정) | 진폭m | **왕복** |
| --- | --- | --- |
| 0.00 | 0.1038 | 4 |
| 0.20 | 0.1211 | 4 |
| 0.40 | 0.1503 | 4 |
| 0.70 | 0.0708 | **4** |

"탄성은 거의 없으면서 모양은 유지하는 재질"이 이걸로 만들어진다.
현실의 천 · 가죽 · 두꺼운 리본이 정확히 그렇다.

### 대가 — 탄성으로 벌던 처짐 저항이 같이 사라진다

탄성 1이 처짐을 잘 잡았던 것은 **주입된 가짜 에너지 덕분**이었다.
매 스텝 되돌리는 힘이 속도가 되고, 그 속도가 다음 스텝에 더 되돌리는 되먹임이
사실상 공짜 복원력으로 작동했다. 그걸 없앴으니 처짐이 늘어난다.

정지 상태 처짐(m) 실측:

| 모양 유지 | 탄성 | 머리카락 | 치마 | 리본 |
| --- | --- | --- | --- | --- |
| 0.00 (끔) | – | 0.0566 | 0.1076 | 0.1860 |
| 0.20 / 0.40 | **1** (예전) | 0.0339 | 0.0064 | 0.0413 |
| 0.20 / 0.40 | 0 | 0.0709 | 0.0818 | 0.1790 |
| 0.70 | 0 | 0.0460 | 0.0432 | 0.0846 |
| 0.90 | 0 | **0.0340** | 0.0209 | **0.0446** |

**탄성 0에서 모양 유지 0.85~0.9면 예전 탄성 1의 처짐 저항을 거의 그대로 되찾는다** —
착지 튐은 없이. 머리카락 0.0340 vs 0.0339, 리본 0.0446 vs 0.0413 으로 사실상 동일하다.

> 주의: 탄성 0에서 모양 유지 **0.2~0.4 는 안 준 것보다 처짐이 클 수 있다**(머리카락 0.0709 > 0.0566).
> 어중간하면 복원 스프링의 접근 속도만 갉아먹고 되돌리지는 못한다.
> **탄성을 0으로 쓸 거면 모양 유지는 확실히 높게 준다.**

다만 모양 유지를 높이면 **움직임도 같이 줄어든다**(걷기 치맛자락 진폭 0.85에서 0.043m).
펄럭임이 필요하면 0.6~0.7 쪽에서 타협한다. 데모 기본값이 치마 0.70 인 이유다.

### 잔향에서는 감쇠만이 탄력을 없앤다

| 가슴 `damping_ratio` | **왕복** | 정착s |
| --- | --- | --- |
| 0.10 | **9** | 1.62 |
| 0.22 | **5** | 0.73 |
| 0.45 | **1** | 0.28 |
| 0.80 | **0** | 0.10 |

| 치마 `drag` | **왕복** | 정착s |
| --- | --- | --- |
| 0.01 | **3** | 0.58 |
| 0.05 | **3** | 0.27 |
| 0.12 | **1** | 0.12 |
| 0.25 | **1** | 0.15 |

데모 01의 ζ = c / (2√k) 가 그대로 나타난 것이다. 강성을 올리면 ζ가 오히려 **내려가서**
더 탄력적이 된다. 한 번 여기된 뒤의 잔향을 줄이려면 감쇠 쪽을 만져야 한다.

`restore_frequency` 도 진짜 스프링이라 같은 함정이 있다. 착지 측정에서 3.0까지 올리면
왕복이 4 → **9** 로 뛴다. 복원을 세게 하고 싶으면 `drag` 도 같이 올려야 한다.

### 왜 "모양 유지 ↓ · 중력 ↓" 이 틀린 처방인가

| 치마 `gravity` (착지) | **진폭m** | 왕복 |
| --- | --- | --- |
| 3.0 | **0.1909** | 4 |
| 9.0 | 0.1503 | 4 |
| 15.0 | **0.0706** | 4 |

- **모양 유지를 낮추면** 처짐이 40배로 돌아온다(위 "모양 유지" 절). 착지 떨림은
  탄성 0에서 애초에 안 생기므로, 모양 유지를 희생할 이유가 없다.
- **중력을 낮추면 진폭이 커진다** (0.071 → 0.191). 왕복은 4로 **전혀** 안 변한다.
  중력은 상수 가속도라 평형점만 옮길 뿐 진동을 감쇠시키지 못한다.

### 뻣뻣한 옷감 레시피 (실측)

데모 프리셋 **"뻣뻣한 천 (덜 탄력적)"** 이 이 조합이다.

```
치마   drag 0.15 · shape_stiffness 0.60 · angle_limit 22°
머리   drag 0.08 · shape_stiffness 0.30 · angle_limit 25°
가슴   damping_ratio 0.45
```

| | 진폭m | 왕복 | 정착s | 처짐m |
| --- | --- | --- | --- | --- |
| 기본 | 0.2132 | 7 | 0.27 | 0.0030 |
| 뻣뻣한 천 | **0.1449** | **4** | **0.12** | **0.0020** |

네 지표가 전부 좋아진다. **그러니 답은 "설정값으로 해결된다"가 맞다** —
다만 만질 값이 모양 유지·중력이 아니라 **감쇠(`drag` · `damping_ratio`)가 먼저**다.

## 새로 얻은 함정

### ① 포화된 값으로는 아무것도 비교할 수 없다

처음에는 `tip_axis` 를 Y와 Z로 바꿔 **가슴 휨 각도**를 비교했다. 결과가 둘 다 정확히 `26.00°`
였다. 축이 무시되는 줄 알았지만, 실제로는 `max_angle_degrees = 26` 에 **양쪽 다 포화**된 것이었다.

> 두 조건을 비교할 때는 **상한에 닿지 않는 양**을 골라야 한다.
> 상한에 걸린 값은 "같다"가 아니라 "잴 수 없다"이다.

바꾼 방법이 훨씬 낫다 — 모디파이어가 믿는 tip 방향(`target_position - bone_origin`)과
**실제 자식 본이 있는 방향** 사이의 각도를 잰다. 축이 맞으면 0°, 틀리면 90°.
포화되지 않을 뿐 아니라 "다른가"가 아니라 **"맞는가"** 를 직접 검증한다.

### ② 정지 상태에서 rest 를 벗어나는 것은 버그가 아니다

처음 검사는 "정지 상태인데 치마가 0.1076m 움직인다"를 실패로 판정했다. 틀린 판정이었다.
중력이 있으면 평형점은 **rest 에서 `g/k` 만큼 옮겨간다.** 데모 01에서 이미 확인한 성질이다.

> 정지 상태에서 재야 할 것은 "rest 에서 얼마나 벗어났는가"가 아니라 **"멈췄는가"** 다.

그래서 프레임 사이의 이동량(잔떨림)으로 바꿨다. 그리고 처짐이 정말 중력 때문인지는
**복원 강성을 2배로 올려 다시 재서** 확인했다.

| | 복원 1배 | 복원 2배 |
| --- | --- | --- |
| 치마 | 0.1076 m | 0.0570 m |
| 리본 | 0.1860 m | 0.0792 m |

이론값(`sag ≈ g/k`, `k = (2πf)²`)대로면 1/4로 줄어야 하는데 **약 1/2만 줄었다.**
거리·각도 제약이 걸려 있어 자유 입자처럼 처지지 못하기 때문이다.
방향은 이론과 맞고 크기는 다르다 — 그래서 계산이 아니라 실측이 필요하다.

### ③ 비교는 "비교 대상이 일하고 있을 때"만 성립한다

모양 유지를 넣자마자 **충돌 검사가 깨졌다.** "충돌을 꺼도 파고듦이 안 늘었다 (0 → 0)".

버그가 아니었다. 치마가 rest 모양을 지키게 되면서 **애초에 다리 근처까지 가지 않게** 된 것이다.
충돌체가 막을 일이 없으니 켜나 끄나 0이 나온다.

> 조건 하나만 바꿔 비교할 때, **그 조건이 실제로 일을 하고 있는 상태**를 먼저 만들어야 한다.
> 아무 일도 안 하는 것을 껐다 켜면 당연히 아무 차이도 안 난다.

그래서 검사를 **둘 다 모양 유지를 끈 상태**(치마가 다리로 무너지는 조건)에서
충돌만 바꾸도록 고쳤다. 그러자 0 → 0.0151m 이 다시 나왔다.

부수적으로 검사 케이스를 인덱스가 아니라 **이름으로** 찾도록 바꿨다.
케이스를 하나 끼워 넣을 때마다 `_results[3]` 이 조용히 다른 줄을 가리키기 때문이다.

### ④ 긴 가닥일수록 기본값이 안 맞는다

데모 03의 머리카락(0.33m)에 맞춰 둔 `restore_frequency 0.9Hz` 를 그대로 쓰면,
0.54m짜리 리본은 정지 상태에서 **18cm나 처진다.** 같은 파라미터인데 결과가 다른 이유는
처짐이 길이에 비례하기 때문이다.

복원 진동수를 올리는 것보다 **`shape_stiffness` 를 쓰는 편이 훨씬 낫다.**
복원 진동수는 사슬을 통째로 제자리에 묶어 흔들림까지 줄이지만,
모양 유지는 꺾이는 것만 막아 **흔들림은 그대로 두면서 처짐만** 없앤다.
실측에서도 복원 2배는 리본 처짐을 0.186 → 0.079m 로 줄인 반면
모양 유지는 0.037m 까지 내리면서 걷기 진폭은 0.16m 를 유지했다.

## 데모에서 해볼 것

허브에서 **09 · 실제 캐릭터 (모디파이어 적용)** 를 고른다.

1. **충돌**을 끈다 → 치맛자락이 허벅지를 통과한다. **충돌체 크기**를 1.6까지 올리면 부풀어 오른다.
2. **치마 각도 제한**을 0으로 내리고 급정거 자극 → 치맛자락이 자기 위로 접히며 메쉬가 뒤집힌다.
3. **치마 반복 횟수** 1 ↔ 12 → 고무줄처럼 늘어났다가 뻣뻣해지고, ms 표시가 같이 오른다.
4. **모델 보기**를 끄고 **사슬 표시**를 켠다 → 본이 실제로 어떻게 움직이는지 그대로 보인다.
5. **가슴 좌우 강성 배율** 0.3 ↔ 1.5 → 좌우로만 / 위아래로만 흔들린다.

## 내장 SpringBone 과 나란히 비교하기

같은 캐릭터에 이 프로젝트의 모디파이어와 엔진 내장 [`SpringBoneSimulator3D`](05_builtin_compare.md)를
각각 붙인 씬을 짝으로 만들어 두었다. **F6 으로 각각 실행해서 본다.**

```
assets/adachi_rigged4/adachi_rigged4_jiggle.tscn    Jiggle
assets/adachi_rigged4/adachi_rigged4_springbone.tscn    내장 SpringBone
assets/adachi_rigged4/adachi_rigged4_compare.tscn       둘을 좌우로 나란히
```

**시뮬레이터는 씬 안에 실제 노드로 들어 있다.** 씬을 열면 트리에 그대로 보이고
인스펙터에서 값을 고칠 수 있다.

```
Rig4Jiggle                               Rig4SpringBone
 ├─ Character (adachi_rigged4.glb)        ├─ Character (adachi_rigged4.glb)
 │   └─ metarig/Skeleton3D                │   └─ metarig/Skeleton3D
 │       ├─ HeadColliderAttachment        │       ├─ SpringHeadCollider
 │       │   └─ HeadCollider              │       ├─ SpringHipCollider
 │       ├─ … 충돌체 4개                   │       ├─ … 충돌체 4개
 │       ├─ Jiggle_Hair_Fringe_002        │       └─ SpringBoneSimulator3D
 │       └─ … 모디파이어 36개              │            (설정 슬롯 36개)
```

비교 씬은 이 둘을 **인스턴스로** 가져와 좌우에 세우고 **자극 하나로 둘 다 움직인다.**
각자 자기 자극을 돌리면 위상이 어긋나 "어느 쪽이 더 흔들리는가"를 판단할 수 없다.
카메라 · 조명 · 바닥도 비교 씬에 하나만 있다.

조작: `1~6` 자극 · `Space` 임펄스 · `R` 리셋 · `Tab` 시뮬레이션 껐다 켜기.

씬을 다시 만들려면 [`tools/make_rig4_scenes.gd`](../tools/make_rig4_scenes.gd).
사슬이 36가닥이라 손으로 적으면 300줄이 넘고 리그가 바뀔 때마다 다시 적어야 한다.

### 눈에 보이는 차이

| | Jiggle | 내장 SpringBone |
| --- | --- | --- |
| 치맛자락 | A라인 형태를 유지 | **안쪽으로 무너져 좁은 통이 된다** |
| 앞리본 | 리본 모양이 남는다 | **납작하게 녹아내린다** |
| 대응 기능 | `shape_stiffness` · `angle_limit` | **없다** |
| 구조 | 사슬 하나 = 노드 하나 (36개) | 시뮬레이터 하나 + 설정 슬롯 36개 |
| 충돌체 | `JiggleCollider3D` + `BoneAttachment3D` | `SpringBoneCollision*3D` (본에 직접) |

내장이 나쁘다는 뜻이 아니다. **거리 제약만 있는 사슬 솔버**라 밧줄·머리카락에는 충분하고
설정도 훨씬 간단하다. 다만 천처럼 **두께가 있어 형태를 유지하는 재질**에는
`shape_stiffness` 에 해당하는 항이 없어서 축 늘어진다.

### 이름이 같은 값 네 개 — 실제로는 다 다르다

| | Jiggle | 내장 SpringBone | 실제 차이 |
| --- | --- | --- | --- |
| **Radius** | `particle_radius` 파티클 두께 | `radius` 조인트 충돌 반지름 | **거의 같다.** 둘 다 미터, 충돌 시 이만큼 띄운다 |
| **Stiffness** | `restore_frequency` (Hz) → rest **위치**로 당기는 가속도 | `stiffness` (0~1 무단위) → rest **방향**으로 되돌림 | Jiggle 은 절대 위치 스프링, 내장은 각도 복원. Jiggle 은 Hz라 "1초에 몇 번"이 물리적으로 정해지고, 내장은 눈으로 맞춰야 한다 |
| **Drag** | `drag` 서브스텝(1/120초)당 속도 감쇠율 | `drag` (0~1 무단위) | **단위가 완전히 다르다.** Jiggle 0.25는 이미 극단값, 내장 0.25는 중간쯤. 이 프로젝트 환산: Jiggle ≈ 내장 × 0.25 |
| **Gravity** | `Vector3`, **m/s² (진짜 단위)** | `float` **무단위** + `gravity_direction` 별도 | **가장 위험한 항목.** 내장에 9.8을 넣으면 중력 항이 스프링 항을 20배 압도해 **흔들림이 통째로 사라진다**(실측: 9.0→0.0065m / 1.0→0.0787m / 0.0→0.277m). 환산 ×1/9 |

`Stiffness` 를 올릴 때 양쪽 다 같은 함정이 있다 — **ζ = c / (2√k)** 이므로 강성만 올리면
감쇠비가 내려가 오히려 더 탄력적이 된다. 반드시 `Drag` 도 같이 올려야 한다.

### 서로에게 없는 값

**Jiggle 에만 있는 것**

| 값 | 내장에 없는 이유 |
| --- | --- |
| `shape_stiffness` · `shape_elasticity` | 내장은 **거리 제약만 있는 사슬 솔버**다. "rest 모양으로 되돌린다"는 개념 자체가 없다. 치마가 무너지는 이유가 이것 하나다 |
| `angle_limit_degrees` | 내장에는 각도 제한이 없다. 대신 `rotation_axis` 로 회전축을 1축으로 묶을 수는 있는데, 이건 "얼마나 꺾이나"가 아니라 "어느 방향으로 꺾이나"라 다른 것이다 |
| `iterations` · `constraint_stiffness` | 내장은 솔버 내부를 안 열어 준다. 길이는 항상 엄격히 유지된다 |
| `collision_response` · `collision_friction` | 내장은 충돌 응답 방식을 고를 수 없다 |
| `respect_animation` | 내장은 [SkeletonModifier3D] 라 **항상 애니메이션 포즈 위에서** 돈다. Jiggle 은 애니메이션 없는 데모용으로 rest 기준이 기본이라 스위치가 필요했다 |

**내장에만 있는 것**

| 값 | Jiggle 에 없는 이유 · 아쉬운 점 |
| --- | --- |
| `individual_config` + 관절별 값 | 관절마다 다른 값. Jiggle 은 곡선으로 대신한다(아래) — 손으로 관절마다 적는 것보다 곡선 하나가 낫다고 봤다 |
| `rotation_axis` | 관절 회전을 한 축으로 제한 |
| `exclude_collision` | 특정 충돌체만 제외 |

**그 뒤에 이쪽으로 옮겨 온 것** — 위 표에 "없다"고 적혀 있던 두 가지는 이제 있다.

| 값 | Jiggle 쪽 | 실측 |
| --- | --- | --- |
| `damping_curve` (radius/stiffness/drag/gravity) | `JiggleChainSettings` 의 `restore_curve` · `shape_curve` · `drag_curve` · `radius_curve` | 복원을 끝에서 0.1배로 낮추니 끝점 흔들림 **0.3494 → 0.5054 m** |
| `center_from` / `center_node` | `motion_inherit` · `teleport_threshold` (사슬에도 생겼다) | 5m 순간이동에서 안전장치 발동 **13회 → 0회** |

`shape_curve` 는 내장에 대응이 없다. 내장에 `shape_stiffness` 자체가 없기 때문이다 —
치마에서 "허리는 형태를 지키고 밑단은 흐물거리게"는 이쪽에만 있다.

곡선을 **네 개만** 둔 이유: `gravity_curve` 는 중력을 마디마다 다르게 주는 것이라 물리가 아니라
연출이고 `restore_curve` 로 거의 같은 그림이 나온다. `angle_limit` 은 메쉬가 자기 위로 접히는 것을
막는 **안전장치**라, 곡선으로 완만하게 풀면 3-④ 함정(각도 제한이 리그 형상과 싸우는 것)을
찾기 어렵게 만든다. 둘 다 넣기는 쉬웠지만 안 넣는 편이 낫다고 판단했다.

> 내장 함정 하나 더 — `get_joint_stiffness(i, j)` 는 `individual_config` 가 꺼져 있으면
> **낡은 기본값(1.0)** 을 돌려준다. 시뮬레이션은 설정값을 제대로 쓴다. getter만 거짓말한다.

### 파라미터 환산 — 같은 이름이라고 같은 단위가 아니다

무대 스크립트가 슬라이더 하나로 양쪽을 몰기 위해 이렇게 환산한다.

| 공통 값 | → Jiggle | → 내장 |
| --- | --- | --- |
| `stiffness` (0~1) | `restore_frequency = stiffness × 3.5` Hz | `set_stiffness` 그대로 |
| `damping` (0~1) | `drag = damping × 0.25` | `set_drag` 그대로 |
| `gravity` (m/s²) | 그대로 | **`× 1/9`** |
| `thickness` | `particle_radius` | `set_radius` |

중력 줄이 가장 중요하다. 내장 `gravity` 는 m/s² 가 아니라 무단위 "중력 세기"라
9.8을 그대로 넣으면 **흔들림이 통째로 사라진다**(→ [05_builtin_compare.md](05_builtin_compare.md)).

## 다른 모델로 바꾸려면

1. `assets/` 에 넣고 `CharacterRig.MODEL` 경로를 바꾼다(비교 씬도 이 상수를 따라간다).
2. `tools/inspect_rig.gd` 의 `MODEL` 도 같이 바꾸고 돌려서 **본 축과 이름 규칙**을 확인한다.
3. `CharacterRig.BONE_AXIS` 와 접두어 상수(`HAIR_PREFIX` · `SKIRT_PREFIX` · `BREAST_BONES`)를 맞춘다.
4. `tools/character_test.gd` 를 돌려 표의 여섯 줄이 위와 같은 모양인지 본다.

카메라와 충돌체 크기는 리그 치수에서 자동으로 잡으므로 건드릴 필요가 없다.
