# 08 · 정점 셰이더 흔들림 — 본 없이 흔들기

> 코드: [`demos/08_shader_jiggle/shader_jiggle_demo.gd`](../demos/08_shader_jiggle/shader_jiggle_demo.gd)

지금까지의 모든 방식은 **본을 움직여서** 표면을 변형시켰다. 이 데모는 본을 하나도 쓰지 않는다.
스킨을 아예 떼어 내고, 정점 셰이더가 표면만 민다.

## 가중치를 어디에 실어 보내는가

스키닝 없이 흔들려면 "여기는 얼마나 움직여야 하는가"를 메쉬 어딘가에 실어야 한다.
이 프로젝트는 [`JiggleBody`](../demos/02_jiggle_bone/jiggle_body.gd) 가 굽는
**정점 색의 알파 채널**에 Jiggle 가중치를 넣는다.

```gdscript
var color := SKIN_COLOR.lerp(JIGGLE_COLOR, amount)
color.a = amount        # ← RGB는 보기용, 알파가 진짜 데이터
```

RGB는 눈으로 보는 색이고 알파가 실제 가중치다. 불투명 재질에서는 알파가 무시되므로
공짜로 딸려 오는 채널이다. (`CUSTOM0` 같은 전용 채널을 써도 되지만 정점 색이 가장 싸다.)

## 두 가지 방식

```glsl
void vertex() {
	float weight = COLOR.a;

	// ① 유니폼 구동: CPU가 스프링 하나로 만든 오프셋을 가중치만큼 분배
	vec3 offset = jiggle_offset * weight;

	// ② 시간 기반: 정점 위치로 위상을 흩어 파도를 만든다
	float phase = VERTEX.x * 9.0 + VERTEX.y * 6.0 + VERTEX.z * 4.0;
	offset += vec3(
		sin(TIME * wobble_frequency + phase),
		sin(TIME * wobble_frequency * 1.3 + phase * 1.7),
		cos(TIME * wobble_frequency * 0.8 + phase)
	) * wobble_amplitude * weight;

	VERTEX += offset;
}
```

| | 유니폼 구동 | 시간 기반 |
| --- | --- | --- |
| 상태 | CPU 스프링 1개 | **없음** |
| 몸의 움직임에 반응 | ○ | ✕ (몸이 뭘 하든 똑같이 출렁) |
| 캐릭터마다 다른 위상 | 유니폼만 다르게 | 정점 위치로 자동 분산 |
| 비용 | 스프링 1개 + 유니폼 갱신 | **완전 공짜** |

유니폼 구동은 데모 02와 원리가 똑같다. 스프링 하나가 관성 때문에 뒤처지고, 그 오프셋을
본 회전 대신 **셰이더 유니폼**으로 내보낼 뿐이다. 본은 0개다.

`VERTEX` 는 모델 공간이므로 월드에서 계산한 오프셋을 반드시 되돌려 넣어야 한다.

```gdscript
var local_offset := body.global_transform.basis.inverse() * world_offset
material.set_shader_parameter("jiggle_offset", local_offset)
```

## 한계 — 마커 두 개로 확인하기

이 데모의 핵심은 화면 가운데 떠 있는 **작은 구 두 개**다.
둘 다 가슴 본에 붙인 [`BoneAttachment3D`](https://docs.godotengine.org/en/stable/classes/class_boneattachment3d.html) 이고,
붙은 방식도 완전히 같다.

> **왼쪽 마커는 흔들림을 따라 움직이고, 오른쪽 마커는 꿈쩍도 하지 않는다.**
> 그래프의 파란 선은 영원히 0이다.

셰이더는 **화면에 그려지는 정점만** 민다. 씬의 어떤 것도 실제로 움직이지 않는다.

| 한계 | 무슨 뜻인가 |
| --- | --- |
| 씬이 안 움직인다 | 장신구·머리카락·옷이 따라오지 않는다. 붙일 게 있으면 못 쓴다 |
| 충돌 불가 | 셰이더는 충돌체를 모른다. 팔이 가슴을 파고들어도 그대로 통과 |
| 읽기 불가 | CPU에서 "정점이 지금 어디 있나"를 물어볼 방법이 없다 |
| 물리 상호작용 불가 | 다른 물체를 밀 수도, 밀릴 수도 없다 |
| 실루엣만 진짜 | 그림자와 외곽선은 흔들리지만 물리적으로는 rest 그 자리에 있다 |

시간 기반 방식에는 하나가 더 있다. **몸이 정지해 있어도 계속 출렁인다.**
`시간 기반 진폭`만 올리고 자극을 `정지`로 두면 바로 보인다. 싸지만 거짓말이다.

## 그래서 언제 쓰나

본 기반이 항상 낫다면 이 기법은 존재하지 않았을 것이다. 셰이더가 이기는 지점은 **개수**다.

- 군중 속 먼 캐릭터 수백 명 — 본을 수천 개 돌릴 수는 없다
- 배경의 풀·나뭇잎·깃발 — 어차피 아무것도 안 붙는다
- 장비를 붙일 일이 없는 부위 (뱃살, 볼살 같은 것)
- LOD의 먼 단계 — 가까울 때는 본, 멀어지면 셰이더로 전환

**결정 기준은 하나다: 거기에 무언가를 붙일 일이 있는가.**
있으면 본, 없으면 셰이더를 고려해도 된다.

## 해볼 것

1. **마커**를 보라. 둘 다 같은 방식으로 본에 붙었는데 왼쪽만 움직인다.
2. **웨이트 보기**를 켜면 셰이더가 읽는 값(정점 색 알파)이 그대로 보인다.
3. **시간 기반 진폭**만 올리고 자극을 **정지**로 → 가만히 있는데도 출렁인다.
4. 프리셋 `둘 다` → 두 방식을 섞는 것이 실무에서 가장 흔한 형태다.
   유니폼 구동으로 큰 움직임을, 시간 기반으로 잔잔한 살아 있는 느낌을 낸다.
