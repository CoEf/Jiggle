### 핵심 설계 결정

1. **데모는 `.tscn` 없이 전부 코드로 씬을 만든다.** 학습 목적상 "이 오브젝트가 어디서 왔는지"가
   인스펙터가 아니라 스크립트 한 곳에 다 보이는 편이 낫다. `main.tscn` 만 예외(UI 레이아웃).
2. **`JiggleDemo` 를 상속하면 UI가 자동으로 붙는다.** `@export_range` 변수를 선언하면
   `ParamPanel` 이 리플렉션으로 슬라이더를 만든다. `get_param_labels()` 로 한글 라벨을 준다.
3. **하나의 솔버, 다른 제약.** `JiggleVerletBody` 가 적분·충돌·안전장치를 전부 갖고,
   `JiggleVerletChain`/`JiggleVerletCloth` 는 `_solve_constraints()` 만 다르게 채운다.
4. **모든 시뮬레이션은 고정 timestep 서브스텝.** 렌더 프레임 delta를 1/120(천은 1/60)로 쪼갠다.

## 3. 반드시 알아야 할 함정 (전부 실제로 당한 것)

> 이 절이 이 문서에서 가장 중요하다. 아래 내용을 모르면 같은 곳에서 몇 시간씩 막힌다.

### ① 모디파이어 결과는 밖에서 읽히지 않는다 — 가장 오래 막혔던 문제

```gdscript
skeleton.get_bone_global_pose(bone)   # ← 항상 rest 값이 나온다
```

`SkeletonModifier3D` 가 쓴 결과는 **스키닝에는 반영되지만**, 바깥에서 읽으면 모디파이어가
돌기 전 값이 나온다. 스켈레톤이 처리 후 로컬 포즈를 되돌리기 때문이다.

이것 때문에 "내장 `SpringBoneSimulator3D` 가 동작하지 않는다"고 한참 오해했다.
실제로는 잘 돌고 있었다. 자작 모디파이어도 마찬가지였다
(`last_usec = 28` 로 멀쩡히 도는데 밖에서는 rest).

| 읽는 방법 | 결과 |
| --- | --- |
| `skeleton.get_bone_global_pose(tip)` | `(0.4, 1.5, 0)` — rest 그대로 |
| **뒤에 붙인 모디파이어 안에서** 같은 호출 | `(0.081, 1.180, 0)` — 실제 결과 |
| `BoneAttachment3D.global_position` | 동일 |

→ `JigglePoseReader3D`(`jiggle/pose_reader_modifier.gd`)를 시뮬레이터 **뒤에** 붙여 읽는다.
자식 순서 = 실행 순서.

같은 성질이 **도움이 되는 경우도 있다.** 모디파이어 *안에서* `get_bone_pose()` 를 읽으면
자기 자신의 지난 프레임 출력이 아니라 애니메이션이 방금 써 넣은 값이 나온다.
`respect_animation` 이 되먹임 없이 동작하는 근거가 이것이다.

### ② Verlet 충돌 — 사고의 90%가 여기서 난다

3단계로 이해해야 한다. `JiggleVerletBody.CollisionResponse` enum 으로 셋 다 실행해 볼 수 있다.

1. **위치만 밀어냄** → Verlet이 그 이동을 속도로 착각 → 매 스텝 에너지가 늘어 **무한대로 폭주**
2. **`previous` 도 같이 밀어냄** → 폭주는 없지만 파고들던 속도가 남아 **표면에서 튄다**
3. **법선 속도를 통째로 버림**(현재 기본값) → 안 튀고 안 터진다. 접선만 마찰로 깎는다

속도 보정은 **반복 루프 안이 아니라 스텝당 한 번만** 해야 한다.
반복 안에서 걸면 반복 횟수를 올릴 때마다 천이 점점 끈끈해진다.

### ③ rest 자세가 충돌체에 파묻히면 파라미터로는 못 고친다

"옆머리만 튀고 뒷머리는 차분하다"는 증상의 원인이었다. 실측으로 확인:

| 조건 | 닿는 가닥 | 안 닿는 가닥 |
| --- | --- | --- |
| 충돌 끔 | 1.07 | 1.07 (**8가닥 완전히 동일**) |
| 충돌 켬 | 3.6 ~ 5.2 | ~1.0 |
| 반복 6 → 16 | 개선 없음 | |
| 마찰 0.2 → 0.6 | 개선 없음 | |
| 리그 형상 수정(어깨 낮춤) | **1.07 (해결)** | |

**교훈: 같아야 할 부위가 다르게 움직이면 그건 튜닝 대상이 아니라 버그다.**
판별법 — ①충돌 꺼 보기 ②대칭 부위 비교 ③파라미터를 극단으로 밀어서 무반응이면 원인 아님.

### ④ 리그 형상 하나가 시뮬레이션을 통째로 망친다

머리카락 뿌리를 머리 꼭대기에 심었더니 첫 마디 rest가 거의 수평이 되었고,
각도 제한(35°)이 **머리카락을 옆으로 뻗친 채 고정**시켰다. 시뮬레이션 코드는 멀쩡했다.
각도 제한의 첫 구간 기준은 rest 방향이므로, **첫 마디는 처음부터 원하는 방향을 봐야 한다.**

### ⑤ 내장 `SpringBoneSimulator3D` 의 `gravity` 는 m/s² 가 아니다

VRM 계열의 **무단위 "중력 세기"** 다. 9.8을 넣으면 중력 항이 스프링 항을 20배 압도해
**머리카락이 아래로 못 박히고 흔들림이 통째로 사라진다.** (바람 같은 직접 외력에는 반응해서
더 헷갈린다.) 실측 진폭: gravity 9.0 → 0.0065m / 1.0 → 0.0787m / 0.0 → 0.277m.
현재 코드는 `gravity * (1.0/9.0)` 로 환산해 넣는다.

부수 효과로, 중력을 정상화하기 전에는 `stiffness` 를 0.02↔0.90 으로 바꿔도 결과가
전혀 안 변했다. 중력 항에 묻혀 있었기 때문이다.

또한 `get_joint_stiffness(i, j)` 는 `individual_config` 가 꺼져 있으면 **낡은 기본값(1.0)** 을
돌려준다. 실제 시뮬레이션은 설정값을 제대로 쓴다 — getter만 거짓말한다.

### ⑥ `PhysicalBone3D` 두 가지

- **`bone_name` 은 노드 이름으로 결정되지 않는다.** 스켈레톤 본 목록으로 만들어지는
  **동적 속성**이라 `add_child` 뒤에 `set("bone_name", ...)` 로 넣어야 한다.
  빠뜨리면 `get_bone_id()` 가 −1이 되고 강체가 **y=44m까지 날아간다.**
- **`body_offset` 은 `IDENTITY` 로 둔다.** "강체 중심을 마디 가운데로" 라며 `(0,−L/2,0)` 을
  넣으면 조인트까지 내려가 사슬이 **기대 길이의 80%로 쪼그라든다**(실측 0.442 / 0.578 / 0.820m).
- 사슬 뿌리 본에도 물리 본이 필요하다(없으면 부모 탐색이 −1에서 끊겨 에러 폭주).
  `physical_bones_start_simulation(["T0", ...])` 로 시뮬레이션 대상에서만 빼면 고정점이 된다.
- **Jolt은 콘 조인트의 `bias`/`relaxation` 을 무시한다**(경고를 낸다).

### ⑦ 그 밖의 엔진 함정

| 함정 | 내용 |
| --- | --- |
| `SurfaceTool.set_skin_weight_count()` | **반드시 `begin()` 앞에서** 호출. 뒤면 에러 |
| 삼각형 감기 | Godot은 **시계 방향**이 앞면 |

| float32 오버플로 | 파티클이 1e19까지 가면 `length_squared()` 가 inf → `normalized()` 가 **0 벡터** → `Quaternion(from,to)` 가 "vectors must not be zero" 에러 |
| 비등방 강성 | k를 축마다 바꾸면 **c도 `2ζ√k` 로 같이 바꿔야** 감쇠비가 유지된다. 안 하면 한 축만 오래 흔들림 |
| 천 바람 | `dot(법선, 바람)` 에 비례시키지 않으면 밀리기만 하고 **펄럭이지 않는다** |
| Verlet | **고정 timestep 필수.** dt가 흔들리면 속도 유추가 깨진다 |

### ⑧ 작업 환경 함정

- **PowerShell로 소스 파일을 편집하지 말 것.** `Get-Content -Raw` + `Out-File`/`Set-Content`
  왕복이 **한글을 전부 깨뜨린다.** 두 번 당했다. 반드시 Write/Edit 도구를 쓸 것.
  (파일 **이동·삭제**는 내용을 건드리지 않으므로 PowerShell로 해도 안전하다.)
- 헤드리스 `--script` 실행 전에 **`--import` 를 한 번 돌려야** `class_name` 전역 등록이 된다.
  안 그러면 "Could not find type ..." 파스 에러가 난다.
  파일을 옮기거나 클래스 이름을 바꿨다면 **반드시 다시 돌릴 것.**
- 스크린샷 자동화는 `_process` 상태 머신 + `await` 조합이 **재진입으로 멈춘다.**
  `_ready()` 안에서 코루틴으로 순차 진행할 것 (`await _wait(n)` → `await _capture(...)`).

### ⑨ `@export` 를 나중에 붙이면 코드로 넣던 값을 조용히 덮어쓴다

코드를 `jiggle/` 로 분리하면서 인스펙터용 `@export` 를 새로 붙였는데, 데모는 슬라이더가 바뀔 때마다
`chain.iterations = ...` 처럼 **솔버를 직접 만진다.** 두 경로가 같은 값을 놓고 싸운다.

지킨 규칙 두 가지. 이걸 안 지키면 데모 거동이 소리 없이 바뀌고, 스모크 테스트는
"터지지 않았는가"만 보므로 **통과해 버린다.**

1. **모든 `@export` 기본값을 솔버 기본값과 정확히 같게 맞춘다.**
   그래야 `_ready()` 에서 인스펙터 값을 밀어 넣어도 아무것도 안 바뀐다.
2. **`@export` 는 세터에서만 솔버에 쓴다.** 매 프레임 덮어쓰지 않는다.
   그래야 코드로 나중에 넣은 값이 이긴다.

`JiggleChainModifier3D.angle_limit_degrees` 의 기본값이 권장값 35°가 아니라 **0(제한 없음)** 인
이유가 이것이다. 기본값을 "좋은 값"으로 두고 싶은 유혹이 있지만, 그러면 규칙 1이 깨진다.

부수적으로 **`var chain` 을 `@export` 들보다 먼저 선언해야 한다.** 세터가 `chain` 을 건드리는데
멤버 초기화는 선언 순서대로 일어나기 때문이다.

### ⑩ 포화된 값으로는 두 조건을 비교할 수 없다

`tip_axis` 를 Y와 Z로 바꿔 **가슴 휨 각도**를 비교했더니 둘 다 정확히 `26.00°` 가 나왔다.
"축이 무시된다"고 판단했지만, 실제로는 `max_angle_degrees = 26` 에 **양쪽 다 포화**된 것이었다.

**상한에 걸린 값은 "같다"가 아니라 "잴 수 없다"이다.** 비교에는 상한에 안 닿는 양을 골라야 한다.

바꾼 방법이 훨씬 낫다 — 모디파이어가 믿는 tip 방향(`target_position - bone_origin`)과
**실제 자식 본이 있는 방향** 사이의 각도를 잰다. 맞으면 0°, 틀리면 90°.
포화도 안 되고, "다른가"가 아니라 **"맞는가"** 를 직접 검증한다.

### ⑪ 정지 상태에서 rest 를 벗어나는 것은 버그가 아니다

"정지인데 치마가 0.1076m 움직인다"를 실패로 판정했다가 틀린 판정이었음을 확인했다.
중력이 있으면 평형점은 **rest 에서 `g/k` 만큼 옮겨간다**(데모 01에서 이미 확인한 성질).

**정지 상태에서 재야 할 것은 "얼마나 벗어났는가"가 아니라 "멈췄는가"다.**
프레임 사이 이동량으로 바꿔야 맞다. 처짐의 원인이 정말 중력인지는 복원 강성을 2배로
올려 다시 재서 확인했다(치마 0.1076 → 0.0570m).

이론값(`sag ≈ g/k`)대로면 1/4이 되어야 하는데 **약 1/2만 줄었다** — 거리·각도 제약 때문에
자유 입자처럼 처지지 못한다. 방향은 이론과 맞고 크기는 다르다. 그래서 실측이 필요하다.

### ⑫ 거리 제약 + 각도 제한만으로는 무엇이든 축 늘어진다

실제 캐릭터에 붙였더니 치마·리본·머리카락이 전부 축 늘어졌다. 파라미터 문제가 아니라
**제약이 하나 없었던 것**이었다.

```
거리 제약   이웃한 두 입자의 간격   → 길이만 지킨다
각도 제한   꺾일 수 있는 최대 각도  → 한계각만 막는다
   그 사이의 모양은 아무도 안 지킨다   ← 비어 있던 자리
```

`JiggleVerletChain.shape_stiffness` 로 채웠다. 각 마디를 **앞 마디가 실제로 돌아간 만큼
따라 돌린 자리**로 끌어당긴다. 절대 방향이 아니라 **앞 마디 기준 상대 방향**을 되돌리는 것이
핵심이다 — 절대 방향으로 하면 사슬이 통째로 굳어 아예 안 흔들린다.

`restore_stiffness`(절대 위치를 rest 로)와 다른 일을 한다. 이쪽은 **꺾이는 것만** 막으므로
흔들림은 그대로 두고 처짐만 없앤다. 실측(정지 처짐, 치마): **0.1076 → 0.0063m**.

반복 루프 안에서 걸므로 **반복 횟수로 나눠 둔다**(`1 - pow(1-s, 1/iterations)`).
안 그러면 충돌 마찰에서 당한 것과 똑같이 반복 횟수를 올릴 때마다 뻣뻣해진다.
반복 횟수는 *제약을 얼마나 정확히 푸는가*여야지 *재질이 얼마나 단단한가*가 되면 안 된다.

### ⑬ 위치를 옮기는 제약은 전부 "없던 속도"를 만든다 — 두 번째로 당했다

`shape_stiffness` 를 켠 뒤 "착지 순간 고무처럼 심하게 진동한다"는 지적을 받았다.
튜닝 문제가 아니라 **③번 충돌 함정과 똑같은 실수를 모양 제약에서 반복한 것**이었다.

```gdscript
positions[i + 1] = positions[i + 1].lerp(target, s)   # previous 를 안 건드렸다
```

Verlet은 속도를 `p - p_prev` 로 유추한다. 그래서 제약이 입자를 옮기면 **그 이동이 그대로
속도가 된다.** 되돌리는 힘이 전부 운동에너지가 되어 반대편으로 넘어간다 = 스프링.
충돌에서는 "폭주"로, 모양 제약에서는 "고무처럼 튐"으로 나타났을 뿐 원인이 같다.

`shape_elasticity` 로 고쳤다. `previous` 를 보정량만큼 같이 옮기면 속도가 안 생긴다.

```gdscript
var correction := (target - positions[i + 1]) * _shape_per_iteration
positions[i + 1] += correction
previous[i + 1] += correction * (1.0 - shape_elasticity)
```

실측(점프 반복, 구동만으로 왕복 4가 나오는 조건):

| `shape_elasticity` | 0.0 | 0.35 | 0.7 | 1.0 |
| --- | --- | --- | --- | --- |
| 착지 왕복 | **4** | 8 | **12** | **12** |

그리고 탄성 0에서는 `shape_stiffness` 를 0 → 0.7로 올려도 왕복이 **4로 고정**이다.
"탄성은 없으면서 모양은 유지하는 재질"이 이걸로 만들어진다.

**대가도 실측했다.** 탄성 1이 처짐을 잘 잡았던 건 그 가짜 에너지가 공짜 복원력으로
작동했기 때문이다. 없애면 처짐이 늘어난다 — 그래서 모양 유지를 더 올려야 한다.

| 정지 처짐(치마) | 모양 끔 | 0.4 / 탄성1 | 0.4 / 탄성0 | 0.9 / 탄성0 |
| --- | --- | --- | --- | --- |
| | 0.1076 | 0.0064 | 0.0818 | **0.0209** |

탄성 0에서 **0.2~0.4 는 안 준 것보다 나쁠 수 있다**(머리카락 0.0709 > 0.0566).
어중간하면 복원 속도만 갉아먹고 되돌리지는 못한다. 쓸 거면 0.8 이상으로 확실히 준다.

> **교훈: Verlet에서 위치를 옮기는 코드를 새로 쓸 때마다 `previous` 를 어떻게 할지
> 반드시 같이 정해야 한다.** 안 정하면 기본값이 "에너지 주입"이고,
> 그 에너지가 어딘가에서 조용히 일을 하고 있어서 없앨 때 다른 값이 같이 무너진다.

### ⑭ "뻣뻣하게" 는 세 가지 다른 요구다 — 탄력을 없애는 건 감쇠뿐

"너무 고무 같다 / 너무 휜다 / 축 늘어진다" 는 전부 "뻣뻣하게 하고 싶다"로 표현되지만
**손잡이가 전부 다르다.** 강성을 올리면 ζ = c/(2√k) 가 오히려 내려가 **더** 탄력적이 된다.

| 증상 | 지표 | 손잡이 |
| --- | --- | --- |
| 착지 순간 튄다 | 착지 왕복 | **`shape_elasticity` ↓** · `restore_frequency` ↓ (⑬) |
| 오래 출렁인다 | 잔향 왕복·정착 | 가슴 `damping_ratio` ↑ · 사슬 `drag` ↑ |
| 너무 많이 휜다 | 진폭 | `angle_limit` ↓ · `gravity` ↑ · `shape_stiffness` ↑ |
| 축 늘어진다 | 처짐 | `shape_stiffness` ↑ |

실측(`tools/material_sweep.gd`) — 감쇠만이 왕복을 줄인다.

| 가슴 `damping_ratio` | 0.10 | 0.22 | 0.45 | 0.80 |
| --- | --- | --- | --- | --- |
| 왕복 | 9 | 5 | 1 | 0 |

| 치마 `drag` | 0.01 | 0.05 | 0.12 | 0.25 |
| --- | --- | --- | --- | --- |
| 왕복 | 9 | 7 | 5 | 2 |

반대로 **중력을 낮추면 진폭이 커지고**(0.168 → 0.260) 왕복은 전혀 안 변한다.
**모양 유지를 낮추면** 왕복은 줄지만 처짐이 40배가 된다 — 탄력이 사라진 게 아니라
축 늘어져 튈 힘조차 없어진 것이다. 자세한 표는 [10_real_character.md](10_real_character.md).

### ⑮ 비교는 "비교 대상이 일하고 있을 때"만 성립한다

⑫를 넣자마자 충돌 검사가 깨졌다 — "충돌을 꺼도 파고듦이 안 늘었다 (0 → 0)".
버그가 아니었다. 치마가 모양을 지키게 되면서 **애초에 다리 근처까지 가지 않게** 된 것이다.

**조건 하나만 바꿔 비교할 때는, 그 조건이 실제로 일을 하고 있는 상태를 먼저 만들어야 한다.**
아무 일도 안 하는 것을 껐다 켜면 당연히 아무 차이도 안 난다.
검사를 "둘 다 모양 유지를 끈 상태에서 충돌만 바꾸기"로 고치자 0 → 0.0151m 이 다시 나왔다.

부수적으로, 검사 케이스는 **인덱스가 아니라 이름으로** 찾아야 한다.
케이스를 하나 끼워 넣을 때마다 `_results[3]` 이 조용히 다른 줄을 가리킨다.

### ⑯ 에디터 밖에서는 `PackedScene.pack()` 이 인스턴스를 통째로 인라인한다

글b 인스턴스 **안쪽**의 `Skeleton3D` 에 모디파이어를 붙인 씬을 코드로 만들려다 당했다.

`PackedScene.instantiate()` 는 기본 모드에서 **"인스턴스 기준 상태"를 안 만든다**
(그건 `GEN_EDIT_STATE_INSTANCE` 인데 에디터 전용이다). 기준이 없으니 `pack()` 은
인스턴스 내부를 전부 "바뀐 것"으로 보고 메쉬·본 데이터까지 써 버린다.
**.tscn 이 1.4MB 가 나왔다.** `scene_file_path` 를 손으로 채워도 소용없다
(인스턴스 줄은 제대로 나오는데 내부 노드가 전부 override 로 따라 붙는다).

해결: **.tscn 텍스트를 직접 생성한다.** 형식이 단순해서 어렵지 않다.

```
[node name="Character" parent="." instance=ExtResource("1_model")]

[node name="Jiggle_Hair" type="SkeletonModifier3D" parent="Character/metarig/Skeleton3D"]
script = ExtResource("4_chain")
root_bone_name = "Hair_Side.L.001"
...
[editable path="Character"]          ← 맨 끝. 이게 있어야 인스턴스 안쪽 자식이 산다
```

같은 씬이 **26KB** 로 줄었다. 표기법이 헷갈리면 한 번 `pack()` 으로 뽑아 보고
그 파일에서 속성 이름을 베끼면 된다(`settings/0/stiffness/value` 같은 것은 추측 불가).

### ⑰ 헤드리스는 프레임 delta 가 제각각이다 — 시간을 재는 검사는 fps 를 고정할 것

`tools/character_test.gd` 가 **4번 중 2번 실패**했다. 코드는 아무것도 안 고쳤는데도 그랬다.
파고듦 값이 `0.0000 / 0.0013 / 0.0151` 로 튀었다.

원인: 헤드리스는 기본이 무제한 fps 라 프레임당 delta 가 제각각이고, 시뮬레이션은
고정 서브스텝(1/120)을 delta 로 채우므로 **같은 프레임 수를 돌려도 흘러간
시뮬레이션 시간이 매번 달라진다.** "그 150프레임 안에 치맛자락이 허벅지까지 왔는가"가
운에 좌우된 것이다.

```gdscript
func _initialize() -> void:
    Engine.max_fps = 60      # 이 한 줄
```

**회귀 검사가 흔들리면 없는 버그를 쫓게 된다. 재현성이 정확도보다 먼저다.**

고치고 나서 드러난 것이 더 중요하다 — 무제한 fps 에서는 delta 가 너무 작아
서브스텝이 거의 안 돌았고, 그래서 그동안 잰 것은 사실상 **과도 상태**였다.

| | 무제한 fps (예전) | 60fps 고정 (지금) |
| --- | --- | --- |
| 걷기 · 치마 진폭 | 0.0909 m | **0.0374 m** |
| 비용 | 1.2 ms | **2.5 ms** |

비용이 2배로 늘어난 것이 아니라 **그동안 과소 보고되고 있었다.** 실제 60fps 앱에서 재면 3.7ms 다.
`tools/material_sweep.gd` 는 처음부터 fps 를 고정해 뒀으므로 그쪽 표는 영향이 없다.

부수적으로, 이 수정 뒤 급정거 자극에서 **끝점이 프레임당 0.9m** 움직이는 것이 드러났다.
관성 기준 좌표계가 없어서 생기는 문제로(4절 4-b), 지금은 `safety_radius` 가 감춰 줄 뿐이다.

**같은 함정을 당시의 인스펙터 경로 검사에서 한 번 더 만났다.** 그쪽은 `character_test` 를 고칠 때
같이 안 고쳤는데, 당시 판단이 "판정 기준을 측정값의 100배로 느슨하게 잡았으니 괜찮다"였다.
틀린 판단이다 — **판정은 안 흔들려도 찍어 둔 숫자는 흔들린다**(사슬 변위가 같은 코드에서
0.2427 / 0.2568 / 0.2572 m). 그러면 실측값을 찍는 이유 자체가 없어진다. 회귀 비교에 못 쓴다.
`Engine.max_fps = 60` 을 넣고 나서야 "리소스 vs `@export` 차이 = 0" 같은 **정확한 등호
비교**가 가능해졌다. 여기서도 길이 오차가 0.01975 → 0.00233 m 로 줄었다(같은 이유 — 그동안
서브스텝이 거의 안 돌았다).

> **숫자를 출력하는 헤드리스 검사는 시간을 재든 안 재든 전부 fps 를 고정할 것.**
> `character_test.gd` · `material_sweep.gd` 둘 다 지금은 60fps 고정이다.

> 남은 흔들림 하나 — `character_test.gd` 의 **정지 계열 6줄은 소수 4자리까지 재현되지만,
> 걷기·급정거 줄은 실행마다 ±7% 정도 움직인다**(걷기 치마 0.0374 ~ 0.0400 m).
> `max_fps` 로도 delta 가 정확히 1/60 은 아니라 서브스텝 개수가 2↔3 을 오가기 때문이다.
> **거동이 안 바뀌었음을 증명할 때는 정지 줄로 비교할 것.** 그쪽은 정확히 일치한다.

### ⑱ 파일을 옮겨도 참조는 안 깨진다 — 그게 문제다

`common/` 에서 `jiggle/` 로 옮겼는데 데모의 **경로 수정이 한 줄도 필요 없었다.**
`class_name` 이 전역이라 파일 위치와 무관하게 이름으로 찾기 때문이다.

편한 대신, `VerletBody` 같은 흔한 이름은 **프로젝트 전역을 차지한다.**
엔진이나 나중에 넣을 다른 코드와 부딪히기 좋아서 전부 `Jiggle` 접두어로 바꿨다.

### ⑲ 세터는 "아직 아무것도 초기화 안 된 시점"에도 불린다

`JiggleChainSettings` 를 붙이면서 `@export var settings` 를 다른 `@export` 들보다 **위에**
선언했다(인스펙터에서 위에 보여야 하므로). 그런데 멤버 초기화는 선언 순서대로 일어난다.

```gdscript
@export var settings: JiggleChainSettings = null: set = _set_settings   # ← 여기서 세터가 불린다
@export_range(1, 32) var iterations := 6                                # ← 아직 0 이다
```

세터가 그대로 `_sync_solver()` 를 불렀다면 **0으로 초기화된 값들이 솔버에 들어간다.**
뒤이어 각 세터가 제 값을 밀어 넣어 결과적으로는 복구되지만, 그건 우연이다.

```gdscript
func _set_settings(value: JiggleChainSettings) -> void:
    if settings == value:      # 초기화 때(null → null) 여기서 끊긴다
        return
```

⑨ 의 "`var chain` 을 `@export` 들보다 먼저 선언해야 한다"와 **완전히 같은 종류**의 문제다.
교훈: **세터에서 다른 멤버를 읽는 순간, 그 멤버가 아직 없을 수 있는 호출 경로가 하나 생긴다.**

### ⑳ 캐시를 그대로 돌려주는 getter 는 재현 안 되는 버그를 만든다

`JiggleChainGroup3D.strands()` 가 캐시를 그대로 돌려주고 있었다. `root_pattern` 이나
`excluded_roots` 를 고친 [b]직후[/b]에 부르면 **옛 목록**이 나온다. 다음 프레임에는
탐색이 다시 돌아 맞게 나오므로 **재현이 안 된다.**

값이 틀린 것보다 나쁘다 — 틀린 값은 다시 재면 또 틀리지만, 이건 "아까는 이상했는데
지금은 맞네"가 된다. 설정을 바꾸는 세터가 dirty 만 세우는 구조라면
**읽는 쪽도 반드시 dirty 를 확인해야 한다.** 검사가 잡았다
(제외 목록에 넣은 뿌리가 그대로 잡히는 것으로 나타났다).

### ㉑ 안전장치가 조용히 일하면 지표가 오히려 좋아진다

순간이동 문제를 재려고 "사슬이 rest 에서 얼마나 벗어났는가"를 봤는데 **0이 나왔다.**
`safety_radius` 가 같은 프레임 안에서 rest 로 되돌려 놓기 때문이다.
즉 **터지는 조건일수록 변위가 더 얌전하게 나온다.**

```gdscript
var safety_resets := 0     # _enforce_safety() 가 일할 때마다 센다
```

세는 것 하나로 문제가 보였다(순간이동 5m 에서 36가닥 중 13회 발동).
3-③ 의 "같아야 할 부위가 다르게 움직이면 버그다"와 짝이 되는 교훈이다 —
**복구 장치가 있는 시스템에서는 "증상이 안 보인다"가 "문제가 없다"를 뜻하지 않는다.
장치가 몇 번 일했는지를 따로 세야 한다.**

### ㉒ `get_skeleton()` 은 노드를 붙인 [b]다음 프레임[/b]부터 값을 준다

```gdscript
skeleton.add_child(modifier)
modifier.get_skeleton()      # ← null. 한 프레임 뒤부터 정상 (실측)
```

엔진이 스켈레톤 캐시를 미뤄서 갱신한다. **시뮬레이션은 다음 프레임부터 돌면 되니 상관없다.**
문제는 **인스펙터는 지금 당장 그려야 한다**는 것이다. 이걸 모르고 짜면 —

- 스켈레톤에 모디파이어를 떨어뜨렸는데 **본 이름 드롭다운이 안 뜬다**(자유 입력칸으로 남는다)
- `JiggleChainGroup3D` 에 이름 규칙을 적었는데 **찾은 목록이 비어 있다**
- 잘못 놓았는데 **설정 경고도 안 뜬다**(스켈레톤이 null 이라 검사를 건너뛰므로)

셋 다 "조용히 아무 일도 안 일어난다"로 보인다. **이 프로젝트가 가장 피하려는 실패다.**

`JiggleBoneNames.skeleton_of()` 로 통일했다 — `get_skeleton()` 이 null 이면 부모를 직접 본다.
모디파이어는 어차피 `Skeleton3D` 의 직속 자식이어야 하므로 부모가 곧 답이다.

> **에디터로 한 번 열어 보기 전에는 이걸 알 수 없었다.** 헤드리스 검사는 전부
> "120프레임 돌린 뒤"를 재고 있어서 이 창을 통째로 건너뛴다.
> **붙인 직후의 인스펙터 상태는 지금 자동 검사가 없다.** 에디터로 직접 열어 볼 것.

3. **좌우 미러 본의 축 부호**를 확인한다. 한쪽만 반대로 흔들리면 여기가 원인.

6. 결과 검증은 **`BoneAttachment3D` 또는 `JigglePoseReader3D`** 로 한다(3-①).
   `get_bone_global_pose()` 로 확인하려 들면 "안 움직인다"는 잘못된 결론에 도달한다.
7. 충돌체는 `JiggleCollider3D` 를 `BoneAttachment3D` 아래에 두면 본을 따라다닌다.

horizontal_ratio 0.7`. 머리카락: `iterations 6 / restore_frequency 0.9Hz / drag 0.03 /
angle_limit 35° / collision_response STABLE / friction 0.2`.

### B-3. 재질 리소스 + 설정 경고  ✅ 완료 (4절 1 · 2번)

```

assets/adachi_rigged4/data/*.tres         튜닝을 끝낸 값 6종 (머리카락 · 치마 · 리본 4종)
```

**1번 — 재질값을 리소스로.** 노드는 "이 가닥이 **무엇**인가"(본 이름 · 축 · 길이 · 충돌체)만
갖고, "**무슨 재질**인가"는 `.tres` 가 갖는다. 지킨 규칙 세 가지:

1. **리소스가 없으면(`null`) 지금까지와 완전히 똑같이 동작한다.** 리소스 기본값 11개가
   노드 `@export` 기본값과 정확히 같아야 한다(`JiggleChainSettings.SHARED_PROPERTIES` 목록).
   **지금은 이 일치를 자동으로 확인하는 검사가 없다** — 한쪽만 고치면 조용히 갈라진다(3-⑨).
2. **리소스가 붙으면 노드 재질값은 인스펙터에서 사라지고 코드로 써도 무시된다.**
   값이 두 군데 보이는데 한쪽만 진짜인 상황을 아예 안 만든다. 떼면 원래 값이 돌아온다.
3. **세터가 전부 `emit_changed()` 를 부른다.** 안 그러면 그 값 하나만
   "슬라이더를 움직여도 반응이 없는데 에러도 안 나는" 상태가 된다.

데모 09 를 이걸로 바꿨다 — **슬라이더 하나가 움직일 때 36개 노드 × 값 11개 대입이
리소스 2개 대입이 됐다**(머리카락 17 + 리본 7이 하나를 공유, 치마 12가 다른 하나).
`character_test.gd` 의 정지 계열 6줄이 소수 4자리까지 동일해 거동은 안 바뀌었다.

**2번 — 설정 경고.** `_get_configuration_warnings()` 를 노드 4종에 붙였다.

| 노드 | 잡는 것 |
| --- | --- |
| `JiggleChainModifier3D` | 직속 자식 아님 · 본 이름 오타 · root↔end 안 이어짐 · `tip_axis` 0벡터 · `tip_length` 0 |
| `JiggleBoneModifier3D` | 직속 자식 아님 · 본 이름 오타 · `tip_length` 0 |
| `JigglePoseReader3D` | 직속 자식 아님 · **시뮬레이터보다 위에 있음** · 읽을 시뮬레이터 없음 |
| `JiggleCollider3D` | 아무 모디파이어도 이 충돌체를 안 씀 |

포즈 리더의 **순서** 경고가 값이 제일 크다 — 위에 두면 조용히 rest 를 읽어 주고,
그게 3-① 에서 가장 오래 막혔던 문제의 원인이다.

> **경고는 에디터에서만 보이므로 조용히 사라져도 아무도 모른다.** 고쳤다면
> `_get_configuration_warnings()` 를 직접 부르는 코드로 **틀린 배치에서 나오는가**와
> **맞는 배치에서 안 나오는가**를 둘 다 확인할 것. 후자를 빼먹으면 "항상 경고"인 구현도
> 멀쩡해 보인다.

### B-4. 곡선 · 관성 기준 좌표계 · 그룹 노드  ✅ 완료 (4절 3 · 4번)

```
jiggle/chain_strand.gd          JiggleChainStrand   — 사슬 한 가닥 (노드 아님)
jiggle/chain_group_modifier.gd  JiggleChainGroup3D  — 이름 규칙으로 여러 가닥
```

**4-(a) 뿌리→끝 곡선.** `JiggleChainSettings` 에 곡선 넷(`restore` · `shape` · `drag` ·
`radius`). 솔버는 곡선을 모르고 **이미 뽑아 놓은 배수 배열**만 본다 — 배열이 비면 전부 1.0
이라 안 쓰는 씬은 영향이 없다. 실측: 복원을 끝에서 0.1배로 낮추니 끝점 흔들림 **0.3494 →
0.5054 m**. `shape_curve` 만 구간별이고, 배수를 **곱한 뒤에** 반복 횟수로 나눠야 한다
(`pow` 가 선형이 아니다).

**4-(b) 관성 기준 좌표계.** `motion_inherit` · `teleport_threshold` 를 사슬에도 넣었다.
둘 다 기본값이 "끔"이라 기존 거동은 그대로다.

| 5m 순간이동 (36가닥) | 안전장치 발동 | 머리카락 | 치마 | 리본 |
| --- | --- | --- | --- | --- |
| 손잡이 없음 | **13회** | 0.7906 | 1.0789 | 1.2632 |
| `teleport_threshold` 1m | **0회** | 0.0262 | 0.0267 | 0.0562 |
| `motion_inherit` 0.5 | 5회 | 0.4453 | 0.5636 | 0.7467 |

문턱을 켠 줄이 **정지 상태와 소수 4자리까지 같다** — 순간이동만 흡수하고 평소는 안 건드린다.
이 표를 얻으려면 먼저 `safety_resets` 를 세야 했다(3-㉑).

**3. 그룹 노드.** 사슬 하나를 흔드는 일 전부를 `JiggleChainStrand`(RefCounted)로 빼고,
`JiggleChainModifier3D` 와 `JiggleChainGroup3D` 가 **같은 것을 돌린다.**

- **자식 노드를 안 쓴다.** 가닥을 자식 노드로 두면 손자가 되어 조용히 안 도는 함정에 빠진다.
- 찾아낸 목록을 인스펙터에 읽기 전용(`found_chains`)으로 보여 준다.
  이름 규칙은 못 찾아도 엉뚱한 것을 잡아도 **조용하기 때문이다.**
- `excluded_roots` 로 규칙에 맞는데 뺄 것을 지정한다. 규칙을 복잡하게 만드는 것보다 낫다.
- `tip_length` 0 이면 가닥마다 마지막 마디 길이를 쓴다.

탐색 결과는 실제 리그에서 확인한다.

```
그룹 이름 규칙 탐색(실제 리그): Hair_* 17/17 · Dress_* 12/12 · *Ribbon* 7/7   (character_test)
```

**진짜 리그에서 재는 것이 중요하다.** 코드로 만든 데모 리그는 곧게 뻗은 몇 마디 한 줄이라
탐색이 할 일이 거의 없다 — 갈래지지도, 규칙에 안 맞는 형제도 없다. 개수만 세지 않고
**뿌리·끝 본 이름까지** 데모 09의 `CharacterRig` 와 맞춰 본다.
