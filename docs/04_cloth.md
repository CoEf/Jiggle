# 04 · 천 Verlet (치마 · 커튼)

> 코드: [`jiggle/verlet_body.gd`](../jiggle/verlet_body.gd),

> [`demos/04_cloth/cloth_demo.gd`](../demos/04_cloth/cloth_demo.gd)

## 사슬과 천은 같은 솔버다

이번 단계에서 데모 03의 Verlet 코드를 [`JiggleVerletBody`](../jiggle/verlet_body.gd) 로 뽑아냈다.
적분 · 충돌 · 접촉 안정화 · 안전장치가 전부 여기 있고,
[`JiggleVerletChain`](../jiggle/verlet_chain.gd) 과
[`JiggleVerletCloth`](../jiggle/verlet_cloth.gd) 는
**무엇을 제약할지만** 다르게 채운다.

```gdscript
# JiggleVerletBody
func step(delta: float) -> void:
	_integrate(delta)
	for iteration in iterations:
		_solve_constraints()      # ← 여기만 다르다
		_solve_collision()
	_resolve_contact_velocity(delta)
	_enforce_safety()
```

| | 제약 | 결과를 읽는 법 |
| --- | --- | --- |
| 사슬 | 거리 + 각도 | 본 회전 |
| 천 | 구조 + 전단 + 굽힘 | **메쉬 정점 그 자체** |

천에는 **본도 스키닝도 없다.** 파티클 위치가 곧 정점이라, 매 프레임 `ArrayMesh`를 다시 굽는다.

## 제약 세 종류 — 각각이 무엇을 막는가

셋 다 **완전히 똑같은 거리 제약**이다. 누구와 누구를 잇느냐만 다르다.

```
구조(structural)  ─│    가로세로 이웃      천이 늘어나는 것을 막는다
전단(shear)       ╲╱    대각선 이웃        정사각형이 마름모로 무너지는 것을 막는다
굽힘(bend)        ─ ─   한 칸 건너뛴 이웃  종이처럼 접히는 것을 막는다
```

구조 제약만 있으면 천은 **평행사변형으로 자유롭게 무너진다.** 격자의 네 변 길이가
그대로여도 각도는 아무 값이나 될 수 있기 때문이다. 그걸 막는 게 대각선(전단)이다.

굽힘은 조금 다르다. 한 칸 건너뛴 두 점의 거리를 유지하려 하면, 그 사이가 접히는 것을
막게 된다. 강하게 걸수록 두꺼운 가죽, 약하게 걸수록 얇은 실크가 된다.

> **직접 확인:** `커튼` + `양쪽 위 모서리만` 고정 → **전단**을 끈다.
> 천이 사각형을 유지하지 못하고 주저앉는다. 다시 켜면 즉시 복구된다.
> 이어서 **굽힘**을 끄면 접힌 자국이 칼처럼 날카로워진다.

제약 개수는 칸 수의 **제곱**으로 늘어난다. 16×11 격자가 이미 1072개다.
`제약 표시`를 켜면 흰(구조) · 파랑(전단) · 주황(굽힘) 격자를 눈으로 볼 수 있다.

## 바람은 법선에 비례해야 펄럭인다

```gdscript
external_accel[i] = direction * (strength * absf(normals[i].dot(direction)))
```

`dot(법선, 바람)` 항이 없으면 천은 **그냥 밀리기만 하고 펄럭이지 않는다.**

펄럭임은 되먹임에서 나온다. 면이 바람을 정면으로 맞으면 세게 밀린다 → 밀려서 돌아간다 →
덜 맞게 되어 힘이 줄어든다 → 중력에 되돌아온다 → 다시 정면으로 맞는다. 이 순환이 파도가 된다.

법선은 어차피 메쉬용으로 매 프레임 계산하므로, 바람은 그걸 재활용할 뿐 추가 비용이 없다.

## 양면 렌더링 — `StandardMaterial3D` 로는 안 되는 부분

천은 앞뒤가 다 보인다. `cull_mode = CULL_DISABLED` 로 양면을 그리면
**뒷면도 앞면과 같은 법선으로 조명되어 새까맣게 나온다.**

Godot의 표준 머티리얼에는 이걸 고칠 스위치가 없어서, 이 데모는 12줄짜리 셰이더를 쓴다.

```glsl
shader_type spatial;
render_mode cull_disabled, diffuse_burley;

void fragment() {
	ALBEDO = cloth_color;
	ROUGHNESS = cloth_roughness;
	NORMAL = FRONT_FACING ? NORMAL : -NORMAL;   // ← 이 한 줄
}
```

## 매 프레임 메쉬 굽기

```gdscript
_cloth.update_normals()
_mesh.clear_surfaces()
_mesh.add_surface_from_arrays(Mesh.PRIMITIVE_TRIANGLES, _cloth.mesh_arrays())
```

인덱스와 UV는 변하지 않으므로 미리 만들어 두고 정점·법선만 갱신한다.
그래도 `add_surface_from_arrays`는 배열을 복사하므로 공짜가 아니다.

측정값(16×11 격자, 195~221 입자, 1032~1178 제약):

| 항목 | 비용 |
| --- | --- |
| 시뮬레이션 (제약 6회 반복) | 1.3 ~ 3.3 ms |
| 메쉬 굽기 | 0.17 ~ 0.20 ms |

**시뮬레이션이 메쉬 갱신보다 10배 이상 비싸다.** 천이 무겁다고 느껴진다면
메쉬 갱신 방식을 최적화하기 전에 제약 반복 횟수와 격자 해상도부터 봐야 한다는 뜻이다.

> `가로 칸수`를 32로 올려 보라. 주황 그래프(프레임 비용)가 어떻게 뛰는지 바로 보인다.

## 치마와 rest 자세 — 데모 03의 교훈을 다시

데모 03에서 배운 것: **rest 자세가 충돌체 안에 파묻히면 파라미터로는 못 고친다.**
치마도 똑같다. 허리 반지름을 골반 충돌체보다 작게 잡으면 복원력과 충돌이 영원히 싸운다.

이 데모는 처음부터 그렇게 되지 않도록 치수를 잡았다.

```
골반 충돌체  중심 y=0.95, 반지름 0.095, 입자 두께 0.008  → 최소 거리 0.103
치마 허리    y=0.97, 반지름 0.180                        → 여유 충분
치마 y=0.94  반지름 0.188, 골반까지 거리 0.118           → 여유 15mm
```

다리는 걷기 위상에 맞춰 흔들리며 치마를 **안쪽에서** 밀어낸다.
천이 몸을 따라 움직이는 것처럼 보이는 이유의 대부분이 이 상호작용에서 나온다.
`파티클 표시`를 켜면 지금 닿아 있는 입자가 빨간 구로 보인다.

## 자기 충돌은 일부러 뺐다

천이 자기 자신을 통과하지 않게 하려면 **모든 입자 쌍**을 검사해야 한다.
200개 입자면 2만 쌍, 800개면 32만 쌍이다. 공간 해시로 줄일 수는 있지만
GDScript에서는 여전히 비현실적이고, 무엇보다 **상용 게임의 천도 대부분 생략한다.**

대신 이렇게 완화한다.

- 굽힘 제약을 걸어 급격히 접히지 않게 한다 (접혀야 관통이 생긴다)
- 파티클에 두께(`particle_radius`)를 줘서 충돌체와 여유를 둔다
- 관통이 눈에 띄는 부위는 애초에 rest 자세를 그렇게 안 만든다

이 데모에서도 치마가 심하게 흔들리면 자기 관통이 보인다. 버그가 아니라 **의도적 생략**이다.

## 해볼 것

1. `커튼` + `양쪽 위 모서리만` → **전단** 끄기/켜기. 사각형이 무너졌다 복구된다.
2. 이어서 **굽힘** 끄기 → 접힌 자국이 날카로워진다. `종이처럼` 프리셋이 이 상태다.
3. **바람**을 26까지 (`깃발` 프리셋) → 법선 비례 바람이 만드는 펄럭임.
4. **제약 표시** 켜기 → 격자의 세 층을 눈으로 확인.
5. `치마` + 자극 `걷기` → 다리가 안쪽에서 밀어내는 것을 빨간 구로 확인.
6. **가로 칸수 32** → 프레임 비용 급증. 제약 수는 칸수의 제곱.
7. **충돌 응답 방식 ①** → 데모 03과 같은 폭주가 천에서도 그대로 재현된다
   (같은 [JiggleVerletBody] 코드를 쓰기 때문).
